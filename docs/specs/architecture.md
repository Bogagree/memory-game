# Architecture

Связано с [decisions.md](../decisions.md). Меняешь границы слоёв — обнови эту спеку и decision.

## Стек

- HTML + CSS + vanilla JavaScript (ES modules)
- Деплой: GitHub Pages ([D-006](../decisions.md))
- Сборщик не требуется, пока страница открывается как статические файлы

## Слои

```text
index.html
css/
  base.css            → токены, базовая типографика
  components.css      → header, board, card, modal
js/
  dom.js              → el(tag, { className, text, attrs, children })
  cards.js            → описание 8 пар: id и src
  shuffle.js          → fisherYates(list) → новый массив
  game.js             → состояние и команды правил
  board.js            → рисует карточки из состояния, отдаёт клики
  header.js           → две кнопки и счётчики
  modal.js            → одна оболочка на оба окна
  leaderboard.js      → чтение/запись localStorage и разметка таблицы
  main.js             → создать UI, подписаться на события, startGame()
assets/images/        → 8 лиц + рубашка
```

`index.html`: в `<head>` — charset, viewport, title, ссылки на CSS. В `<body>` — только `<script type="module" src="js/main.js"></script>`.

## Правила модулей

- `el()` внутри вызывает `document.createElement`, вешает класс, `textContent`, атрибуты и детей через `append`. HTML-строк не принимает.
- `game.js` не импортирует DOM, модалку и `localStorage`. Он хранит состояние и отвечает на команды: `startGame`, `flipCard(id)`, `cancelMismatch`.
- Наружу игра сообщает о смене состояния. `main.js` по этому сигналу обновляет поле, счётчики и при победе один раз сохраняет результат и открывает модалку.
- `modal.js` не знает, победа это или рейтинг. Ему передают готовое содержимое и кнопки.
- Одинаковые действия «Новая игра» в хедере и в модалке победы вызывают одну функцию.

## Поток

```text
load → startGame → shuffle → render face down
click card → game.flipCard
  match → counters, maybe win → leaderboard.save once → modal.open(win)
  mismatch → lock → timeout 1000ms → face down → unlock
header New game / win New game → clearTimeout → startGame → modal.close
header Leaderboard → modal.open(table)  // поле не трогать
```

## Контракт `feat/app-shell`

Шаг только собирает пустой экран:

- `el()` и модули-заготовки без правил переворота.
- Хедер с двумя кнопками ([header.md](./header.md)). Кнопки пока могут не иметь поведения, кроме того что они есть в DOM и доступны.
- Счётчики показывают «0 ходов» и «0 из 8» ([counters.md](./counters.md)).
- Контейнер поля без карточек.
- «Просмотр кода страницы» показывает пустой `body` и один `script`.

## Контракт `feat/board`

Шаг заполняет поле и не включает правила переворота:

- После загрузки в `.board` 16 кнопок `.card`. Ни у одной нет класса `card--flipped`.
- Восемь `pairId`, каждый дважды. Лицо — `img` из `assets/images/`. Рубашка одна и та же.
- Счётчики остаются «0 ходов» и «0 из 8». Кнопки хедера не `disabled`.
- Порядок колоды фиксированный. Перемешивание — `feat/shuffle`.
- Клик по карточке не меняет класс и не меняет счётчики.

## Контракт `feat/shuffle`

Шаг меняет только порядок колоды:

- `fisherYates(list)` в `js/shuffle.js` возвращает новый массив и не меняет исходный. Это алгоритм Фишера–Йейтса, не выбор из готовых раскладок.
- Загрузка вызывает `startGame`: перемешать `createDeck()` и нарисовать 16 закрытых карточек.
- Повторная загрузка может дать тот же порядок. Это допустимо.
- «Новая игра» пока не вызывает `startGame`. Клик по карточке её не открывает.

## Контракт `feat/flip-pair`

Шаг открывает карточки и не считает ходы:

- Первая закрытая карточка переворачивается и остаётся ждать вторую.
- Вторая карточка с тем же `pairId` остаётся открытой. Можно открывать следующую пару.
- Повторный клик по открытой или уже найденной карточке не меняет поле.
- Две разные карточки остаются открытыми, новые клики по полю их не закрывают и не открывают третью.
- На экране по-прежнему «0 ходов» и «0 из 8». Кнопки хедера ничего не делают.

## Контракт `feat/mismatch-counters`

- Ход +1 только когда открылась вторая карточка. Совпадение добавляет одну пару. Текст счётчиков пишется через `textContent` из состояния.
- Клик по первой, уже открытой, найденной или третьей карточке во время `locked` счётчики не меняет.
- Несовпавшая пара видна 1000 мс. В это время третья карточка не открывается, кнопки хедера остаются доступны. Затем обе карточки закрываются.
- Восемь найденных пар переводят игру в `won`. Модалка и запись результата не открываются. «Новая игра» таймер не отменяет.

## Контракт `feat/win-modal`

- Оболочка — нативный `<dialog>` и `showModal()`. Содержимое передаётся снаружи: `modal.js` не различает победу и рейтинг.
- Восемь пар открывают окно один раз. Внутри заголовок «Победа», число ходов этой партии, кнопки «Новая игра» и «Закрыть».
- Закрытие: кнопка «Закрыть», клик по затемнённому фону, Escape. Клик по заголовку, числу ходов и панели окно не закрывает.
- Пока окно открыто, у `html` и `body` есть класс `modal-open` (`overflow: hidden`). После закрытия класс снимается и страница возвращается к прежней позиции прокрутки. Карточки и кнопки хедера недоступны.
- Закрытие не меняет поле и счётчики. Фаза остаётся `won`, дальнейшие клики по карточкам ничего не меняют.
- Второе окно поверх уже открытого не открывается.
- «Новая игра» в окне и в хедере рестарт не запускает. «Таблица лидеров» окно не открывает. Запись результата не делается.

## Контракт `feat/leaderboard`

- Переход в `won` один раз дописывает `{ moves, playedAt }` в `localStorage` по ключу `memory-game-results`. `playedAt` — ISO-время. Флаг `resultSaved` не даёт записать дубликат при повторном открытии окон.
- «Таблица лидеров» открывает ту же оболочку. Пустой список — текст «Пока нет результатов», без `table`. Иначе таблица: место, ходы, дата `ДД.ММ.ГГГГ`, не больше 10 строк.
- Меньше ходов выше. При равных ходах выше более ранняя партия. В хранилище остаётся вся история.
- Открытие и закрытие не меняют поле, счётчики и таймер несовпадения. Таймер доигрывает за окном.
- «Новая игра» рестарт не запускает и ключ не очищает.
